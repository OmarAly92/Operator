# Tauri port bugs and deferred work

**Audit date:** 2026-08-25  
**Audited commit:** `08363d324` on `master`  
**Release decision:** `stop-port`

This is a code, test, workflow, packaging, and documentation audit of the Tauri desktop port. A checked test suite is not evidence that the app is bug-free: the audit found production paths that current fakes and native tests do not exercise. During this audit, Rust Clippy passed, all 214 Rust tests passed, TypeScript and Tauri E2E typechecks passed, all 1,720 renderer tests passed, the 15 Electron-absence checks passed, the 17 state-audit unit tests passed, the 9 native build-contract tests passed, and the 102-row parity ledger checker passed. The Phase 0 decision still failed with `stop-port` because macOS, Windows, Linux, application-identity, and updater-signing evidence is missing.

Priority meanings: **P0** is a credential or code-signing emergency; **P1** blocks a safe public Tauri release or breaks required parity; **P2** is a real correctness, confinement, or CI defect that should be fixed after P0/P1.

## Bugs

- [x] **P1 — Tauri development could not start the Go daemon from its actual working directory.** The Rust process starts from `frontend/src-tauri`, while development discovery treated that directory as `frontend` and resolved the daemon working directory as the nonexistent `frontend/backend`. Spawning therefore failed with `No such file or directory (os error 2)`. Fixed on 2026-08-25 by normalizing a `src-tauri` application path to its frontend parent before resolving `../backend`, with a regression test in `frontend/src-tauri/src/daemon/tests.rs`.

- [x] **P1 — Tauri development loaded browser-preview demo data instead of real daemon data.** `beforeDevCommand` launched `dev:web`, which intentionally compiles with `VITE_RENDERER_PREVIEW=1`; the native window therefore displayed `opr-demo` fixtures and demo terminals. Fixed on 2026-08-25 by adding a separate `dev:tauri` Vite command without the preview flag and reserving `dev:web` for renderer preview and Playwright.

- [ ] **P0 — Feature-release jobs expose production signing identities and repository-write access to PR code.** The job checks out a PR head and then runs its dependency lifecycle, build scripts, local actions, Tauri build, and feed generator while the release environment, `contents: write`, updater private key, Apple credentials, and write-capable token are available. The workflow can also explicitly allow fork PRs. An approved malicious or compromised PR can exfiltrate signing material, sign malicious artifacts, or mutate releases. Evidence: `.github/workflows/feature-release.yml:36-40`, `:183-218`, `:238-303`, `:386-457`, and `:510-550`. Fix by compiling PR code in an unprivileged job, attesting the immutable output, and signing/publishing it in a trusted base-branch job that executes no PR-controlled code.

- [ ] **P1 — A packaged update check can panic and terminate Operator.** The normal shell registers clipboard, dialog, notification, opener, and optional global-shortcut plugins, but never registers `tauri_plugin_updater` (`frontend/src-tauri/src/lib.rs:942-957`). The production feed client nevertheless calls `app.updater_builder()` (`frontend/src-tauri/src/updater/mod.rs:915-935`). In pinned `tauri-plugin-updater` 2.10.1, that accessor requires plugin-managed `UpdaterState`; without it, Tauri state lookup panics. Operator's panic hook exits the process (`frontend/src-tauri/src/lib.rs:390-399`). The 214 Rust tests miss this because they inject a fake feed client. Register and configure the plugin in normal builds, then add a packaged integration test that performs a real signed manifest check without exiting.

- [ ] **P1 — Update installation is exposed in the UI but is not implemented.** Settings and sidebar buttons promise “Restart & install” and call `updates_install` (`frontend/src/renderer/components/settings/UpdatesSection.tsx:247-257`, `frontend/src/renderer/components/Sidebar.tsx:1012-1072`), but the command always returns `APPLY_DEFERRED_MESSAGE` (`frontend/src-tauri/src/updater/mod.rs:629-630`). The click sites discard the rejected promise, so users receive no useful recovery UI. Implement a project-owned, signed apply/restart/rollback path whose temporary and recovery data stays under the Operator state root, and test install, upgrade, downgrade, interruption, and rollback on all three operating systems.

- [ ] **P1 — Stable releases can become public while incomplete and before acceptance gates finish.** Every parallel platform leg creates a public, non-draft release and uploads its own artifacts (`.github/workflows/frontend-release.yml:171-186`). Feed generation waits for the matrix later (`:419-454`), while the native E2E gate is explicitly advisory and is not a `publish-feed` dependency (`:329-331`, `:409-425`). If one matrix leg fails, GitHub can expose a partial “latest” release without all installers or `latest.json`. Publish only after every artifact, trust, Phase 0, signed-update, and native-acceptance gate passes; stage artifacts privately until one fail-closed conductor atomically publishes the release.

- [ ] **P1 — Release verification does not prove updater key binding or native trust on Windows/Linux.** Stable builds consume the compiled public key and signing private key independently (`.github/workflows/frontend-release.yml:55-58`, `:97-105`). Artifact verification and feed generation validate signature encoding/shape but do not verify each signature against the public key compiled into the app (`frontend/scripts/verify-tauri-artifacts.sh:311-335`, `frontend/scripts/tauri-feed.mjs:146-179`). A mismatched pair can publish updates every installed client rejects. Authenticode and RPM trust checks are also nonfatal gates (`frontend/scripts/verify-tauri-artifacts.sh:636-641`, `:703-707`), and the release workflow has no Windows or Linux native-signing step. Make public/private-key binding, Authenticode, and Linux package trust fatal before publication.

- [ ] **P1 — Persisted locale hydration races daemon startup and permanently falls back to English.** The renderer blocks its first mount on `useLocaleStore.load()` (`frontend/src/renderer/main.tsx:73-76`), while the daemon is started concurrently just before the window is built (`frontend/src-tauri/src/lib.rs:1057-1063`). Until the mounted daemon-status hook learns the port, API calls return a synthetic 503 (`frontend/src/renderer/lib/api-client.ts:189-197`, `frontend/src/renderer/hooks/useDaemonStatus.ts:15-55`). The locale store catches that first failure, applies English, and marks itself loaded without retry (`frontend/src/renderer/stores/locale-store.ts:34-54`). Gate settings hydration on daemon readiness or retry it, and add a cold-launch native test using a non-English persisted locale.

- [ ] **P1 — Persisted shortcut overrides have the same startup race and can be overwritten.** Root fires one unguarded load after mounting (`frontend/src/renderer/routes/__root.tsx:24-26`); the store has no readiness wait, retry, or rejected-load recovery (`frontend/src/renderer/stores/keybindings-store.ts:27-40`). Its Tauri getter requires daemon-backed settings (`frontend/src/renderer/lib/tauri-bridge.ts:315-321`). If startup returns 503, renderer and native accelerators keep defaults; editing one shortcut then merges against `{}` and can erase unrelated persisted overrides. Hydrate only after daemon readiness, serialize edits behind hydration, and verify renderer plus native accelerators after a full app relaunch.

- [ ] **P1 — Native notification clicks cannot activate or navigate Operator.** `notification_show` discards the notification ID after checking it and constructs a toast with title/body only (`frontend/src-tauri/src/native.rs:210-245`). `route_click` and `notifications:click` exist only as an uncalled policy abstraction and renderer subscription (`frontend/src-tauri/src/notification_policy.rs:49-57`, `frontend/src/renderer/lib/tauri-bridge.ts:244-254`). Add real macOS and Windows activation handlers that focus the main window and emit the correct notification ID, with packaged click-through E2E.

- [ ] **P1 — Native WebDriver CI cannot reach E2E because a required bundle resource is not prepared.** The workflow builds daemon and ACP resources but omits `npm run browser-runtime:prepare` (`.github/workflows/tauri-webdriver.yml:68-80`). Tauri requires the `../agent-browser/` resource (`frontend/src-tauri/tauri.conf.json:20-27`). Current macOS, Windows, and Linux runs fail during the normal-shell build with “resource path ../agent-browser doesn't exist,” before WebDriver starts. Prepare the resource in the workflow and require all three native jobs to reach and pass the packaged test suite.

- [ ] **P2 — Completed update downloads are forgotten after app restart.** Engine state always starts with `staged: None` (`frontend/src-tauri/src/updater/mod.rs:209-234`), startup only recovers interrupted partial downloads (`:1244-1269`), and the duplicate-download check consults only the in-memory staged value (`:431-449`). Storage persists verified artifacts and metadata (`frontend/src-tauri/src/updater/storage.rs:132-150`), but they are not rehydrated. Restore staged state from disk, validate its signature/metadata, and test restart without redownloading.

- [ ] **P2 — Stable packaged macOS builds create a tray that policy says is nightly-only.** `is_tray_enabled` permits packaged trays only for nightly versions (`frontend/src-tauri/src/tray.rs:96-98`), and tests assert that rule, but production never calls it. `create_tray` checks only the operating system (`:414-417`) and startup invokes it unconditionally (`frontend/src-tauri/src/lib.rs:1109-1125`). Apply the policy at the creation boundary and add stable/nightly packaged tests.

- [ ] **P2 — External-preview acknowledgement failures can either lose the acknowledgement or open duplicate browser tabs.** `postPreviewOpenedAck` silently succeeds when the trusted daemon base is not ready (`frontend/src/renderer/lib/tauri-bridge.ts:100-108`), so the trigger is consumed and never acknowledged. For HTTP/transport failures, `openExternalPreview` rejects only after the external browser already opened (`:237-242`); `useExternalPreview.retry` repeats the complete open-plus-ack operation (`frontend/src/renderer/hooks/useExternalPreview.ts:77-110`, `:132-139`), opening another tab. Track “opened” and “acknowledged” separately and retry only the acknowledgement.

- [ ] **P2 — Standalone browser runtime creates state outside the required Operator root.** Unix socket aliases default to `/tmp` (`backend/internal/adapters/agentbrowser/runtime.go:89-96`, `:156-161`) and `ensureRunRoot` creates `opr-br-*` symlinks there (`:501-554`). Crash cleanup depends on a later scavenger (`:925-965`), and the Tauri state audit does not watch `/tmp` (`frontend/scripts/audit-tauri-state.mjs:18-73`). Move the alias beneath the resolved state root or explicitly revise the confinement contract and audit every allowed exception.

- [ ] **P2 — Shift+Enter sends an agent-specific escape sequence in plain shell terminals.** The xterm handler deliberately emits `ESC+CR` for every pane even though the source states that this is unintended and untested for login shells (`frontend/src/renderer/components/XtermTerminal.tsx:549-566`). Scope meta-return to compatible agent TUI panes and preserve normal shell input semantics elsewhere.

- [ ] **P2 — The parity checker certifies behavior without verifying status meaning or evidence.** It accepts any nonempty status string (`frontend/scripts/check-parity-ledger.mjs:151-206`). The ledger therefore marks update install and notification click as covered (`frontend/perf/parity-ledger.json:713-720`, `:849-855`) even though both are absent. Constrain the vocabulary, require resolvable test/evidence references, and reject claims whose required implementation is deliberately stopped.

- [ ] **P2 — The retired Phase 0 workflow is invalid rather than disabled.** `.github/workflows/tauri-phase0.yml:1-16` removes the `on:` key but retains jobs, causing workflow-startup failures with zero jobs instead of a clean retirement. Delete it, add a valid non-triggering mechanism, or replace it with the required trusted evidence producer.

- [ ] **P2 — Port completion records contradict the binding acceptance criteria.** `.superpowers/sdd/2026-08-20-tauri-port/progress.md:467` says the plan is complete, but the plan's native, signed-update, cross-platform, and performance checklist remains incomplete (`docs/superpowers/plans/2026-08-20-tauri-port.md:1115-1172`) and the binding decision remains `stop-port` (`docs/benchmarks/tauri-port-baseline.md:54-91`). Correct the completion language to “implementation sequence ended; release blocked” so future agents and release conductors cannot treat it as release approval.

## Deferred work

- [ ] **Embedded in-app browser panel.** Keep the panel, toolbar, viewport controls, and pop-out UI out of this release; external browser preview remains the current behavior. Product questions and capability losses are tracked in `docs/todo/browser-panel-webview.md`.

- [ ] **Binding Phase 0 and performance evidence.** Produce authorized macOS, Windows, and Linux evidence from the same commit and artifact set: first/warm launch, idle memory/CPU, terminal-open latency, throughput, sustained-output behavior, input latency, reconnect and cleanup correctness, artifact/download size, and installed footprint. Measure the standalone managed browser separately. Do not change `stop-port` without trusted evidence.

- [ ] **Cross-platform packaged acceptance.** After repairing native CI, run real packaged Tauri binaries on macOS, Windows, and Linux. Cover renderer/xterm typing and buffer output, reconnect/pooling, menu actions using the renderer's real `view.*` contract, shortcuts, tray, theme, overlay, clipboard, chooser, fullscreen, notifications, and failure artifacts. Current terminal E2E tests REST and raw WebSocket seams instead of the rendered terminal, and current settings E2E checks REST persistence without renderer rehydration.

- [ ] **Signed install, migration, recovery, and rollback proof.** Run fresh install, Electron-to-Tauri migration, upgrade, downgrade, interrupted download/apply, recovery, rollback, and artifact trust checks on all supported operating systems after the updater bugs above are fixed.

- [ ] **State-root proof and reliability.** Fix and rerun the Darwin state-audit shutdown-timeout case, include browser socket aliases and temporary paths in confinement checks, prove all native/webview/updater/browser/terminal state placement on every OS, bound abandoned relocation staging, close daemon supervision shutdown/start windows, and harden the intermittent relocation-lock timing test.

- [ ] **Feature/nightly update services.** Implement or explicitly waive shell-side GitHub feature-build and escalation transports. Production currently uses stopped transports, so feature listing, pin retirement, and important/nightly escalation are unavailable. Add a valid scheduled nightly producer before nightly is advertised.

- [ ] **Updater transport and cryptographic hardening.** Replace whole-artifact `Vec<u8>` downloads and `fs::write` with bounded streaming, cancellation, timeouts, partial recovery, and disk-space handling. Add compiled-key mismatch, signature binding, startup failure, escalation race, and time-zone boundary tests.

- [ ] **Native capability and CSP hardening.** Enforce a restrictive CSP in the Tauri shell as well as the generated renderer meta tag, split state-audit and benchmark permissions from the normal production capability, and narrow direct global-shortcut permissions to the minimum required commands.

- [ ] **Native titlebar decision.** Obtain explicit product sign-off for decorated native titlebars on macOS and Windows, or implement and verify the coordinated drag-region/titlebar migration.

- [ ] **Terminal/chat portability design.** Decide whether first TUI-to-Chat switches import provider visual history and whether in-flight tool calls can be transferred. This requires provider identity, deduplication, and execution-transfer contracts; it is not a renderer-only parity fix.

- [ ] **Test and benchmark tooling debt.** Narrow the xterm bundle exemption, correct possible CSS-size double counting, use path-safe heap containment checks, validate benchmark arguments consistently, avoid permanently caching rejected lazy imports, upload native E2E/benchmark artifacts, remove dead environment switches, eliminate reload races, and run release rather than debug binaries wherever acceptance requires production behavior.
