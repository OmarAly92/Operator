# Settings › Mobile / ngrok — renderer plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a **Mobile** tab to the Settings dialog that holds every mobile control, split the Connect Mobile modal's body into shared section components, and build the ngrok section (credential, API key + account, session/agent, diagnostics + live log) over the daemon routes from the daemon plan.

**Architecture:** One hook (`useMobileBridge`) owns every query and mutation; three section components (`MobileConnectionSection`, `MobilePublicAccessSection`, `NgrokSection`) render from it; `GlobalSettingsForm` composes them for `section === "mobile"`, and `ConnectMobileModal` becomes a shell over the first two. Copy goes through i18n `en.json`; other locales fall back.

**Tech Stack:** React 19, TanStack Query, zustand (`useUiStore`), shadcn primitives in `components/ui`, react-i18next, Vitest + Testing Library, `openapi-fetch` typed `apiClient` (types regenerated by the daemon plan's Task 9).

**Spec:** `docs/superpowers/specs/2026-09-19-mobile-settings-ngrok-design.md` (section 6).

**Depends on:** the daemon plan (`2026-09-19-mobile-settings-ngrok-daemon.md`) landed on `development`, so `frontend/src/api/schema.ts` already has the `/api/v1/mobile/tunnel/ngrok…` paths and `MobileTunnelStatus.lastProvider/fallbackReason`.
