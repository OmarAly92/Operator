Scope of plan 4 (Flutter, `packages/mobile` only):
- **Tickets on the Agents board**: a `Planned` zone / section that lists open tickets (status not `done`/`archived`) for `single_repo` projects, with a filter chip per `sessions_filter.dart`'s idiom and the section header idiom; a ticket card (title, project chip, status line incl. the planning session's activity, one row per plan with `NN`, title, status pill using the board's status colours, tap-through to the plan's session), and an Archive section entry for `done`/`archived` tickets with `Reopen`. Scratch/workspace projects get the one-line "tickets need a single-repository project" hint only when no repo project exists. Tickets refresh with the board (`getBoard()` extended or a parallel `TicketsRepository` called from the same cubit tick — decide, cite, and keep the sequential-auth rule).
- **Ticket detail screen** (`RoutesStrings.ticket`, args `projectId` + `slug` + optional `file`): header (title, brief, status pill, warning banner for unreadable tickets), file list (`ticket.md`, `spec.md`, plans with status pills and their kickoff files, planning session row), and a **read-only** markdown preview of the selected file via `flutter_markdown_plus` styled like `block_markdown.dart`, with the frontmatter rendered as a key/value block above the body (port `splitFrontmatter` from `frontend/src/renderer/lib/ticket-presentation.ts:138-160` to Dart with tests). No editor on mobile in this plan (§3.7 "the editor later"); say so in the header.
- **Actions**, each a bottom sheet in the spawn/`session_actions_sheet` idiom: `Plan with agent` (harness, model, Claude account, extra → `POST …/plan`, then open the session); `Assign` on `todo` and `Reassign` on `terminated` plans (read-only ticket / plan / project / branch `opr/<slug>-NN` with the suffix hint; editable harness, model, account, extra; dry run on open with one line per warning in human copy for all five codes; `Start` / `Terminate and start`; re-check the dry run on submit, stop on a new warning, `force` only when warnings exist, kill the fresh live session id first; navigate to the new session); `Review` (planner | new session); `Merge` confirmation showing `mergeSummary` (spec §2.6, mirrors desktop `MergeConfirmDialog`); `Mark done`; `Archive` / `Reopen`; `New ticket` (title, brief) from the Planned section header. Every failure shows the envelope's `message` and keeps `requestId` visible.
- **Session ↔ ticket link**: parse `ticket` into `SessionModel`; show a `slug · NN` / `slug · plan` chip on session cards and in the session detail header; tapping opens the ticket detail with that file selected.
- **Copy** is inline English (no catalogue on mobile); the five warning strings and the status labels should match the desktop English in `frontend/src/renderer/i18n/en.json` (`tickets.*`) so both clients read the same.
- Out of scope: editing files on the phone, drag and drop, backend or desktop changes, push notifications for tickets.
