title: CLI reference
description: Commands provided by the current Go CLI.

The `opr` CLI is a thin client for the local Operator desktop app and its loopback daemon. Product commands require the desktop app to be running. Run `opr <command> --help` for the exact flags supported by your installed version.

## Command tree

```text
opr
├── start                         Open the desktop app (download it when needed)
├── stop                          Stop the local daemon
├── status                        Show daemon health
├── doctor                        Check the local Operator environment
├── agent ls                      List built-in agent adapters and readiness
├── project                       add, ls, get, set-config, rm
├── spawn                         Create a worker or orchestrator session
├── session                       ls, get, kill, restore, rename, cleanup, claim-pr,
│                                 switch-agent, agent-switch
├── orchestrator ls               List orchestrator sessions
├── send                           Send a message to a session
├── pr                             merge, resolve-comments
├── review                         ls, trigger, cancel, submit
├── preview                        select/clear a target; start, status, stop a server
├── browser                        Control the selected session browser
├── import                         Import projects from legacy Operator data
├── completion                     Generate shell completions
└── version                        Print build information
```

Internal commands such as `daemon`, `hooks`, `launch`, `agent-process`, and `pty-host` are intentionally omitted.

## Desktop and daemon

### `opr start`

Opens the installed Operator desktop app. If no app is installed, the legacy launcher can fetch the latest desktop release first. It does not supervise the daemon itself.

| Flag | Purpose |
| --- | --- |
| `--json` | Print the launch result as JSON. |

For a new installation, download the desktop app from the [installation guide](/docs/installation). The frozen npm package is a legacy launcher, not the current distribution channel.

### `opr stop`

Asks the loopback daemon to shut down after checking that the run file identifies Operator.

| Flag | Purpose |
| --- | --- |
| `--timeout <duration>` | Maximum time to wait for shutdown. |
| `--json` | Print the result as JSON. |

### `opr status`

Reports daemon state, process identity, run-file location, health, and readiness. This command does not list sessions.

| Flag | Purpose |
| --- | --- |
| `--json` | Print structured daemon status. |

Use `opr session ls` for sessions.

### `opr doctor`

Checks Operator configuration, the data directory and database, daemon state, Git, GitHub authentication, and the platform runtime (`tmux` on macOS/Linux; ConPTY is built into Windows).

| Flag | Purpose |
| --- | --- |
| `--json` | Print checks as JSON. |

## Projects and agents

### `opr agent ls`

Lists the daemon's built-in agent catalog together with local installation and authentication readiness.

| Flag | Purpose |
| --- | --- |
| `--refresh` | Rerun bounded local install/auth probes. |
| `--json` | Print the raw inventory response. |

Agent adapters are compiled into Operator. There is no plugin marketplace or `opr plugin install` command.

### `opr project`

| Command | Purpose |
| --- | --- |
| `opr project add` | Register a local Git repository or multi-repository workspace. Scratch is an Operator-managed built-in project. |
| `opr project ls` | List registered projects. |
| `opr project get <id>` | Show one project and its resolved configuration. |
| `opr project set-config <id>` | Update typed per-project configuration. |
| `opr project rm <id>` | Remove a project registration. |

Project configuration is persisted by the daemon in SQLite. `set-config` supports common flags and `--config-json`; it does not edit `operator.yaml`. Use command help for the complete typed fields.

## Sessions

### `opr spawn`

Creates a session in a registered project. The command takes no positional arguments and requires a display name.

```bash
opr spawn --name fix-login --project my-app --agent codex --prompt "Fix the login regression"
```

Important flags include:

| Flag | Purpose |
| --- | --- |
| `--name <name>` | Required sidebar name, at most 20 characters. |
| `--project <id>` | Project to use. Otherwise Operator resolves environment and current directory context. |
| `--agent`, `--harness <name>` | Override the project's agent. The two names are aliases. |
| `--kind worker\|orchestrator` | Select the session role. |
| `--mode chat\|tui` | Select structured Chat or the agent's native terminal UI. |
| `--branch <name>` | Branch for Git projects. Scratch projects do not support it. |
| `--prompt <text>` | Initial prompt. |
| `--issue <id>` | Associate a tracker issue. |
| `--claim-pr <ref>` | Claim an existing pull request after spawning. |
| `--no-takeover` | Refuse a PR already owned by another active session. |
| `--skip-agent-check` | Skip only the CLI-side install/auth preflight. |

Project resolution order is explicit `--project`, `OPERATOR_PROJECT_ID`, the project of `OPERATOR_SESSION_ID`, then the closest registered project containing the current directory. Before spawning, Operator refreshes the selected agent's advisory readiness unless `--skip-agent-check` is set.

### `opr session`

| Command | Purpose |
| --- | --- |
| `opr session ls` | List active worker sessions. Use `--all` for orchestrators and `--include-terminated` for history. |
| `opr session get <id>` | Show one session. |
| `opr session kill <id>` | Terminate a session. Dirty workspaces are preserved. |
| `opr session restore <id>` | Relaunch a terminated session. |
| `opr session rename <id> <name>` | Change its display name. |
| `opr session cleanup` | Reclaim eligible terminated workspaces; supports `--dry-run`. |
| `opr session claim-pr <session-id> <pr-ref>` | Attach an existing GitHub PR. |
| `opr session switch-agent <id> <target-harness>` | Switch a compatible session to another harness. |
| `opr session agent-switch ls <session-id>` | Inspect agent-switch attempts. |

Most lookup commands accept `--project` to disambiguate a session ID.

### `opr send`

Sends a message through the daemon to a running session.

```bash
opr send --session opr-123 --message "Please address the failing test"
```

Both flags are required. When called from a session with `OPERATOR_SESSION_ID`, Operator prefixes the sender identity.

### `opr orchestrator ls`

Lists orchestrator sessions. Add `--json` for structured output.

## Pull requests and reviews

| Command | Purpose |
| --- | --- |
| `opr pr merge <pr-number>` | Request a merge through Operator's GitHub action engine. |
| `opr pr resolve-comments <pr-number> [comment-id...]` | Resolve selected or eligible review comments. |
| `opr review ls <worker-session-id>` | List review state for a worker. |
| `opr review trigger [worker-session-id]` | Start or restart a reviewer run. Aliases: `execute`, `restart`. |
| `opr review cancel [worker-session-id]` | Cancel a reviewer run. Alias: `stop`. |
| `opr review submit [worker-session-id]` | Submit a reviewer verdict and results. |

Use each subcommand's help for required review-run IDs, verdict values, and file/stdin inputs.

## Preview and browser control

### `opr preview [url]`

Selects what the desktop Browser panel displays for the session identified by `OPERATOR_SESSION_ID`. With no argument Operator looks for a supported static entry point in the session workspace; with a file or `file:`, `http:`, or `https:` target it opens that target.

| Command | Purpose |
| --- | --- |
| `opr preview clear` | Clear the selected preview. |
| `opr preview start [configuration]` | Start exactly one command from `.operator/launch.json`, wait for readiness, and select it. |
| `opr preview status` | Show the managed preview process and recent bounded logs. |
| `opr preview stop` | Stop the managed process tree. |

`.operator/launch.json` is optional project configuration. Operator does not infer or scaffold development servers, and static files do not require one.

### `opr browser`

Controls the live, session-isolated Electron browser owned by the desktop app. It also resolves its target from `OPERATOR_SESSION_ID`; the desktop app must be open.

The command family includes status/open, accessibility snapshots and references, click/drag/fill/type/press/hover, highlight, scroll, select/check state, property reads, tabs and popups, DevTools, frames, dialogs, waits, screenshots, console/page errors, and bounded opt-in network metadata capture.

References become stale after navigation, DOM replacement, frame changes, or tab changes. Take another snapshot when Operator reports `STALE_REFERENCE`. Network capture is off by default, metadata-only, bounded, and automatically expires.

## Migration and shell integration

| Command | Purpose |
| --- | --- |
| `opr import` | Import legacy projects from `~/.operator`; supports `--dry-run`, `--yes`, and `--json`. Unsupported legacy plugin settings are reported as dropped. |
| `opr completion bash\|zsh\|fish\|powershell` | Generate a shell completion script. |
| `opr version` / `opr --version` | Print build metadata. |

## Environment

| Variable | Default | Purpose |
| --- | --- | --- |
| `OPERATOR_PORT` | `3001` | Loopback daemon port. |
| `OPERATOR_RUN_FILE` | `~/.operator/running.json` | Daemon identity and port handshake. |
| `OPERATOR_DATA_DIR` | `~/.operator/data` | Daemon data directory. |
| `OPERATOR_REQUEST_TIMEOUT` | `60s` | REST request timeout. |
| `OPERATOR_SHUTDOWN_TIMEOUT` | `10s` | Graceful shutdown limit. |
| `OPERATOR_SESSION_ID` | unset | Current session context for preview, browser, and in-session calls. |
| `OPERATOR_PROJECT_ID` | unset | Current project context for spawn resolution. |

All current Operator application state stays under `~/.operator` unless `OPERATOR_DATA_DIR` or `OPERATOR_RUN_FILE` overrides it.
